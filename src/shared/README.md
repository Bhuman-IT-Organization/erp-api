# shared/

Cross-cutting, generic, never module-specific. Unversioned: `v1/` and a future `v2/` both use it. Nothing under `shared/` imports from `v1/`; where `shared/` needs module behaviour (the access-token verifier) it declares a port and the module provides it.

`health/` is not in the approved plan's list of `shared/` subfolders; it was added here because the container healthcheck and Nginx both need `/health` before any other layer exists.

`resilience/` is ADR-0031's home for retry, breaker and timeout; the `transport/` row of the approved plan (HTTP client factory) is superseded by it — outbound HTTP is Node's built-in `fetch` wrapped by `withRetry`, a breaker and `timeoutSignal`, and a module's `service/<module>.transport.ts` is the only file that calls them.

## Rules this folder owns

- **TIMINGS rule (ADR-0031 §1):** every duration or threshold constant lives in `config/timings.ts` as the frozen `TIMINGS` object, grouped by concern. Env holds deployment-varying values only (URLs, secrets, flags, the pool budget); TTLs and timeouts are never env variables. The only exceptions are `connection_limit` in the rendered `DATABASE_URL` (the environment's pool budget) and the two `RESILIENCE_BREAKER_*` overrides, which exist for the local stack proof and are refused in production.
- **Guards depend on the `ACCESS_TOKEN_VERIFIER` port; `v1/auth` provides it.** `JwtAuthGuard` and `PermissionGuard` only call `verifyAccessToken` / `hasPermission`; the Redis and JWT work is the verifier's. Use `@UseGuards(JwtAuthGuard, PermissionGuard)` + `@Permissions(PERMISSIONS.staff.members.view)` — a clean ADR-0033 name from `@erp/contracts`, never a Perfex code — and read `@CurrentUser()`.
- **Errors leave the api as problem details.** Throw `new AppError('ERP-…')` anywhere; `ProblemDetailsFilter` maps it. Unknown errors become `ERP-INTERNAL-0001` with the fixed detail `Internal error`; the original goes to the logger only.
