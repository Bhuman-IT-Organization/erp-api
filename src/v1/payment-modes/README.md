# payment-modes

## Purpose

The Payment Modes list (W2A-04): list, read, create, update, the one-click active switch, delete and the four-format export of the client's own offline payment modes, the ones Perfex's invoices, payments, expenses, credit notes, accounting, purchase, fixed_equipment and timesheets offer, replacing Perfex's `admin/paymentmodes` screen (`controllers/admin/Paymentmodes.php`, `models/Payment_modes_model.php`, `views/admin/paymentmodes/manage.php` and `paymentmode.php`, `views/admin/tables/payment_modes.php`). Started as a copy of erp-docs `05-templates/backend-module` (forms: singular `payment-mode`, plural `payment-modes`) and reshaped to the table's columns on the Cost Centers module's shape; the screens live under `/setup/payment-modes` in erp-web (a Setup > Finance item), the api under `api/v1/payment-modes`. Online gateways (Stripe, PayPal, ...) are configured in Perfex's Settings and are not listed here, as Perfex's own list does not list them (D-32).

## Owned tables

- `tblpayment_modes`: claimed for `node` in the ownership register by plan 04.1-22 (W2A-04), written here through Prisma's typed delegate, which the ownership guard admits because the register names `node`. Node writes the seven columns of Perfex's form: `name` (`VARCHAR(100)`), `description` (`MEDIUMTEXT`), `active` (`TINYINT(1)`) and the four `INT` boxes `show_on_pdf`, `selected_by_default`, `invoices_only` and `expenses_only`; `id` is assigned by the database. A create and an update write all seven (Perfex's edit rewrites every field), an unticked or absent box saving 0 (`Payment_modes_model.php` :100-102, :143-145); the switch writes `active` only. Perfex's own screen was its one writer (D-32): no co-writer. The table has no show-to-client column, and none is written (D-35).

The description is stored exactly as Perfex's `nl2br_save_html` stores it (`application/helpers/template_helper.php` :116-136: PHP's `nl2br` when the text holds no closing tag on one line, otherwise each line right-trimmed and given `<br />` unless it ends in a tag) and read back as its `clear_textarea_breaks` reads it (:92-107: `<br />`, `<br>` and `<br/>` removed in any letter case, then PHP's `trim`), so Perfex's invoice PDFs and screens show a Node-saved description unchanged, and a read value saved again is stored byte-identically (D-34).

Read only, never written (DB-03):

- `tbloptions.expense_credit_payment_mode` (unattributed), through `SettingsFacade` (`settings/index.js`, the allow-list's 31st name) from the transport; read as PHP's `(int)` reads it (`Expenses_model.php:109`), used only when above 0, never logged and never answered (only `isCreditExpenseMode` is). A lock on delete only (D-37).
- `PAYMENT_MODE_REFERENCES` (the repository's docblock), what refers to a payment mode, for each row's usage and the delete refusal (D-33). A declared candidate list; before every usage read ONE `information_schema.COLUMNS` probe (every table and column name bound) answers which candidates the connected schema has, and only those run (D-28). A missing candidate counts 0 and raises no error, and the probe is never cached, so a column a module's install lacks is counted the moment it exists, with no code change. This module never adds a column to any table (never patch Perfex). Each present candidate is one tagged `$queryRaw` over all the ids at once (table and column names literal, the ids bound with `Prisma.join` as decimal TEXT), in one `Promise.all`; an error from the probe or any statement rejects the whole answer (fail closed). Every column is text because it also holds online gateway ids, so a mode counts only where the column holds its id's decimal text EXACTLY: `CAST(r.<column> AS BINARY) IN (...)` compares the bytes (no collation, no padding, no number conversion: `'07'`, `' 7'`, `'7 '` and `stripe` never count for 7):

The accounting mappings (`tblacc_payment_mode_mappings.payment_mode_id`, `tblacc_expense_category_mapping_details.payment_mode_id`) and the "allowed" lists (`tblinvoices.allowed_payment_modes`, serialized; `tblfe_cart.allowed_payment_modes`): Perfex allows deleting a mapped or allowed mode, so they do not block a delete (D-33).

## Facade surface

- `describe(): { module: 'payment-modes'; version: 1 }`
- `findById(id: number): Promise<PaymentMode | null>`
- `listAll(): Promise<readonly PaymentMode[]>`: every payment mode, the name ascending, then the id; refused loudly (`ERP-INTERNAL-0001`) above `PAYMENT_MODES_FACADE_MAX_ROWS` (1,000), never truncated
- `findByIds(ids: readonly number[]): Promise<readonly PaymentMode[]>`: in the order given, each id once, absent ids skipped

`PaymentMode` is `{ id, name, active, invoicesOnly, expensesOnly, selectedByDefault, showOnPdf }`, every flag a boolean (Perfex reads each box as `== 1`), never the wire DTO or the description. No facade method writes or asserts the administrator flag: a module-to-module read has no actor. **Who uses it:** the invoices and payments, expenses and purchase migrations, `listAll` for a payment mode picker (the caller filters `active`, `invoicesOnly` and `expensesOnly` and merges its own online gateways, as Perfex's `Payment_modes_model::get()` does; gateways stay theirs to merge) and `findByIds` for the names a document's ids point at. Other modules import only `src/v1/payment-modes/index.ts` (the facade and the `PaymentMode` / `PaymentModeId` types) and `PaymentModesModule`.

## Endpoints

Under `api/v1/payment-modes` (`PAYMENT_MODES_ROUTES` in `payment-modes.routes.ts`). All seven are administrators only (D-06, D-32): every handler carries `JwtAuthGuard, PermissionGuard` and declares no permission code, and the service asserts the administrator flag as the first statement of every use case, so a member holding every catalogue code is still refused. Perfex's own controller was administrator-only too (`Paymentmodes.php:11`). `@erp/contracts`' `ROUTE_GATES` declares the three screens `'admin'` and `__tests__/route-gates.spec.ts` compares every handler with it. Every failure is an RFC 9457 problem (`application/problem+json`) with an `ERP-*` code: 400 `ERP-VALIDATION-0001` (+ `issues`), 401 `ERP-AUTH-0004`, 403 `ERP-AUTH-0005` (detail `payment modes are managed by administrators only`).

| Method   | Path         | Success                                                                                                                                                                                                          | Errors beyond the three                                                                 |
| -------- | ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `GET`    | ``           | 200 `{ data, meta: { nextCursor, prevCursor, total, rangeStart, exportLimit, printLimit } }`, each row the record; `?limit&cursor&q&sort` (`name` default, `-name`, `id`, `-id`, `active`, `-active`)            | none                                                                                    |
| `GET`    | `export`     | 200 by `?format=`: `csv` (absent), `xlsx`, `pdf` (each `attachment; filename="payment-modes-YYYY-MM-DD.<ext>"`) or `print` (JSON rows, no attachment); `no-store`; columns `id`, `name`, `description`, `active` | 400 on `export` over the format's cap; on `key` (no row selection); on `font` for a PDF |
| `GET`    | `:id`        | 200 the record                                                                                                                                                                                                   | 404 `ERP-CORE-0004`                                                                     |
| `POST`   | ``           | 201 the record                                                                                                                                                                                                   | none                                                                                    |
| `PATCH`  | `:id`        | 200 the record                                                                                                                                                                                                   | 404 `ERP-CORE-0004`                                                                     |
| `PATCH`  | `:id/active` | 200 `{ id, active }`                                                                                                                                                                                             | 404 `ERP-CORE-0004`                                                                     |
| `DELETE` | `:id`        | 204, no body                                                                                                                                                                                                     | 404 `ERP-CORE-0004`; 409 `ERP-PAYMENTMODES-0002`, then `ERP-PAYMENTMODES-0001`          |

The record is `{ id, name, description, active, showOnPdf, selectedByDefault, invoicesOnly, expensesOnly, usage, isCreditExpenseMode }`: the id as text, the description in its read form, the five boxes as booleans, `usage` the eight counts (`invoicePayments`, `expenses`, `creditNoteRefunds`, `purchaseInvoicePayments`, `purchaseOrderPayments`, `debitNoteRefunds`, `fixedEquipmentRefunds`, `orderReturnRefunds`) and `isCreditExpenseMode` whether Perfex's credit option names the mode. The body of `POST` and `PATCH :id` is the seven fields, strict: `name` required, trimmed, 1 to 100 characters (`PAYMENT_MODES_NAME_MAX`), every character accepted and stored as text (`<` and `>` included, rendered as text), a name another mode holds accepted; `description` any text (absent saves `''`); `active`, `showOnPdf`, `selectedByDefault`, `invoicesOnly`, `expensesOnly` booleans, each absent one saved as 0; any other key (the show-to-client flag, `id`, `usage`, ...) is a 400 naming it, and `{}` on `PATCH` is a 400 on `['name']`. The switch's body is `{ active }`, strict; it writes `active` only, and a flag already so answers 200 with no write, no event and no log line. `q` matches the name or the description (contains, under the columns' collation) and, when `q` is all digits up to 2147483647, the id. The description is not a sort (nullable MEDIUMTEXT); `active` is (NOT NULL; it pages with equality, Prisma having no `gt` or `lt` on a Boolean). The export runs on the shared core (`shared/http/export.ts`), administrators first for every format; neither the usage nor the setting is read; `active` is `1`/`0` in CSV and Excel and the sent yes or no word in PDF and Print; CSV and Excel escape a leading formula character in every cell and header label.

`ERP-PAYMENTMODES-0002` (DELETE, checked first; the usage is then never read): Perfex's `expense_credit_payment_mode`, cast as PHP's `(int)`, is above 0 and equals the mode's id; detail `expenses use this payment mode to mark a credit expense (a Perfex setting), so it cannot be deleted; switch it off instead to stop offering it`. `ERP-PAYMENTMODES-0001` (DELETE): any group of `PAYMENT_MODE_REFERENCES` is non-zero (`used by 2 invoice payment(s), 1 expense(s) and 4 order return refund(s); switch it off instead to stop offering it`, the non-zero groups only, in the order `invoice payment(s)`, `expense(s)`, `credit note refund(s)`, `purchase invoice payment(s)`, `purchase order payment(s)`, `debit note refund(s)`, `fixed equipment refund(s)`, `order return refund(s)`), or the usage answer does not name the id (`its use could not be counted`). Nothing is deleted and no event is published on a refusal. A detail names counts or the reason only, never a name or the setting's value.

## Events published

| Event                                | When                                      | Payload                                             |
| ------------------------------------ | ----------------------------------------- | --------------------------------------------------- |
| `payment-modes.record.created`       | after `POST` stores it                    | `{ id, at }`, `PaymentModesCreatedV1`               |
| `payment-modes.record.updated`       | after `PATCH :id` saves it                | `{ id, at }`, `PaymentModesUpdatedV1`               |
| `payment-modes.record.activeChanged` | after `PATCH :id/active` changes the flag | `{ id, active, at }`, `PaymentModesActiveChangedV1` |
| `payment-modes.record.deleted`       | after `DELETE` removes it                 | `{ id, at }`, `PaymentModesDeletedV1`               |

Declared in `events/published.ts` (`PAYMENT_MODES_PUBLISHED_EVENTS`), published through `DOMAIN_EVENT_PUBLISHER` from `service/payment-modes.transport.ts`. A payload carries the id (and the switch's flag) and the server time, never the name, the description or the setting. One `activeChanged` event with the flag, the custom-fields shape, rather than an `activated` and a `deactivated`. After each publish the service writes one `LoggerService.log` line, `payment mode created|updated|activated|deactivated|deleted` with `{ id }`, which carries `requestId` and `staffId` from the request context (D-36, BE-10). Node writes no row to Perfex's activity log, where Perfex wrote one per add, edit, delete and status change (`Payment_modes_model.php` :119, :169, :193, :271): the event and the log line are Node's record (D-36, D-18), a release-note item.

## Resilience

- **Breaker:** none: no outbound HTTP, no vendor call; the settings facade is an in-process call.
- **Retry policy:** none on writes: an unkeyed `POST` retried could create two rows, and the events are in-process.
- **Pool budget:** shares `POOL.db.api` (`connection_limit` in `DATABASE_URL`, asserted by `check:db`); a list page costs the page, two counts, the probe, one statement per present candidate (eight at most) in one `Promise.all` and the `expense_credit_payment_mode` read; no extra DB or Redis client.

## How to run its tests

```bash
corepack yarn test src/v1/payment-modes          # unit, the repository over a stub client (D-33), the gates and the in-process controller e2e spec (no network, no database)
corepack yarn test:int src/v1/payment-modes      # the repository against the local stack (node ../erp-infra/scripts/local-up.mjs first)
```

The int spec writes only `tblpayment_modes` rows whose name starts with `int-spec-04.1-23-pm` and deletes them before and after the run; it never writes a Perfex-owned table and never reads a local value into an assertion message.
