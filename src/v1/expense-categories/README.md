# expense-categories

## Purpose

The Setup list of expense categories (W2A-01, the Wave 2a pilot): list, read, create, update and a CSV export of the categories Perfex's expense forms pick from, replacing Perfex's `admin/expenses/categories` screen. Started as a copy of erp-docs `05-templates/backend-module` and reshaped to the table's columns; the screens live under `/setup/expense-categories` in erp-web, the api under `api/v1/expense-categories`.

## Owned tables

- `tblexpenses_categories`: claimed for `node` in the ownership register by plan 04.1-02 (D-09), and written here since plan 04.1-04 through Prisma's typed delegate, which the ownership guard admits because the register names `node`. Node writes `name` (`VARCHAR(191)`) and `description` (`MEDIUMTEXT`, nullable); `id` is assigned by the database.

`description` is stored in Perfex's `nl2br` form (`toStoredDescription`) and read in its `clear_textarea_breaks` form (`fromStoredDescription`), both in `service/expense-categories.transformer.ts`, so Perfex keeps reading the rows Node writes.

Read only, never written (DB-03), for the delete refusal and the list's usage counts (D-07, D-15):

- `tblexpenses.category`: the expenses filed under the category (Perfex's own delete checks it).
- `tblacc_expense_category_mappings.category_id`: accounting's category mappings.
- `tblpur_petty_cash_advances.expense_category`: purchase's petty cash advances, counted **whenever the table exists**. The purchase module creates it on install and the local copy lacks it, so every usage read first asks `information_schema.TABLES` whether it exists (the table name bound as a value, never cached), then runs one grouped count with the ids bound. An error from either query is not caught: the list shows its retryable error and a delete is refused, never allowed on an unknown count.

Two other writers of `tblexpenses_categories` stay on Perfex as recorded coexistence co-writers until their modules migrate (D-14, the register note): `POST /admin/expenses/category` (the inline "+" on Perfex's expense form, which non-administrators can use too when Perfex's inline-create option is on) and `/admin/timesheets/add_expense_category` (it writes through `Expenses_model::add_category`). A category added there publishes no Node event; that is accepted (D-14).

## Facade surface

- `describe(): { module: 'expense-categories'; version: 1 }`
- `findById(id: number): Promise<ExpenseCategory | null>`: the model in its stored form, never the wire DTO

Other modules import only `src/v1/expense-categories/index.ts` (the facade and the `ExpenseCategory` / `ExpenseCategoryId` types); the architecture block in `eslint.config.mjs` rejects a deeper path.

## Endpoints

Under `api/v1/expense-categories` (`EXPENSE_CATEGORIES_ROUTES` in `expense-categories.routes.ts`). All six are administrators only (D-06): every handler carries `JwtAuthGuard, PermissionGuard` and declares no permission code, and the service asserts the administrator flag as the first statement of every use case, so a member holding every catalogue code is still refused. `@erp/contracts`' `ROUTE_GATES` declares the three screens `'admin'` and `__tests__/route-gates.spec.ts` compares every handler with it. Every failure is an RFC 9457 problem (`application/problem+json`) with an `ERP-*` code: 400 `ERP-VALIDATION-0001` (+ `issues`), 401 `ERP-AUTH-0004`, 403 `ERP-AUTH-0005` (not an administrator).

| Method   | Path     | Success                                                                                                                                                                                                                                                                                                                                          | Errors beyond the three                                                                                               |
| -------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------- |
| `GET`    | ``       | 200 `{ data, meta: { nextCursor, prevCursor, total, rangeStart, exportLimit, printLimit } }`, each row with `expenseCount`, `mappingCount`, `pettyCashCount`; `?limit&cursor&q&sort` (`name` default, `id`)                                                                                                                                      | none                                                                                                                  |
| `GET`    | `export` | 200 by `?format=`: `csv` (absent; `text/csv; charset=utf-8`, BOM), `xlsx`, `pdf` (each `attachment; filename="expense-categories-YYYY-MM-DD.<ext>"`) or `print` (`application/json` rows, no attachment); `no-store` always; `?q&sort&column&header...` and, for pdf and print, the presentation parameters; columns `id`, `name`, `description` | 400 on `export` over the format's cap; on `key` (no row selection); on `font` for a PDF the standard font cannot draw |
| `GET`    | `:id`    | 200 `{ id, name, description }`                                                                                                                                                                                                                                                                                                                  | 404 `ERP-CORE-0004`                                                                                                   |
| `POST`   | ``       | 201 the category                                                                                                                                                                                                                                                                                                                                 | none                                                                                                                  |
| `PATCH`  | `:id`    | 200 the category                                                                                                                                                                                                                                                                                                                                 | 404 `ERP-CORE-0004`                                                                                                   |
| `DELETE` | `:id`    | 204, no body                                                                                                                                                                                                                                                                                                                                     | 404 `ERP-CORE-0004`; 409 `ERP-EXPENSECATEGORIES-0001` while in use                                                    |

The bodies accept exactly what Perfex accepts (D-19): `name` is required, trimmed and 1 to 191 characters (`EXPENSE_CATEGORIES_NAME_MAX`, the `VARCHAR(191)` column) with no character refused; `description` is optional with no Node cap (the column is `MEDIUMTEXT`; the only ceiling is the api's existing request-body limit). Both bodies are strict: any other key is a 400 naming it. Names and descriptions are stored and answered literally; a screen renders them as text (T-4.1-07). `q` matches the name or the description (contains). The cursor is opaque and bound to its `sort`; another sort's cursor, a tampered one or a `filter[...]` is a 400. **The export (ADR-0043)** runs on the shared core (`shared/http/export.ts`), administrators first for every format: `format` is `csv` (absent), `xlsx`, `pdf` or `print`; `column` picks a subset of the columns in canonical order; `header` carries one translated label per exported column; `key` is a 400 on its path, because the list has no row selection (D-27); `limit` and `cursor` are 400s on theirs. The core counts first and refuses more than 10,000 rows for csv and xlsx, or 1,000 for pdf and print, on path `export` with `params: { limit, total }` before reading a row (the list meta carries both caps, `exportLimit` and `printLimit`). Its cells are the response fields, the description in its read form, and the usage counts are never exported. CSV and Excel escape a leading formula character in every text cell and header label; PDF and Print show the text as is, and a PDF whose text the standard font cannot draw (a name in Arabic) is refused on path `font` (D-24) while Print of the same list answers it.

`DELETE` refuses with 409 `ERP-EXPENSECATEGORIES-0001` while `usageByCategory` reports any expense (`tblexpenses.category`), accounting mapping (`tblacc_expense_category_mappings.category_id`) or petty cash advance (`tblpur_petty_cash_advances.expense_category`) for the id (D-07, D-15); the detail names the three counts (`used by N expense(s), N accounting mapping(s) and N petty cash advance(s)`), and a usage answer that does not name the id fails closed. Nothing is deleted and no event is published. The list rows carry the same three counts so a screen can refuse up front; the 409 stays for the race (T-4.1-05, accepted: Perfex's own delete has the same window).

## Events published

| Event                               | When                      | Payload                                    |
| ----------------------------------- | ------------------------- | ------------------------------------------ |
| `expense-categories.record.created` | after `POST` stores it    | `{ id, at }`, `ExpenseCategoriesCreatedV1` |
| `expense-categories.record.updated` | after `PATCH` saves it    | `{ id, at }`, `ExpenseCategoriesUpdatedV1` |
| `expense-categories.record.deleted` | after `DELETE` removes it | `{ id, at }`, `ExpenseCategoriesDeletedV1` |

Declared in `events/published.ts` (`EXPENSE_CATEGORIES_PUBLISHED_EVENTS`), published through `DOMAIN_EVENT_PUBLISHER` (`shared/events/`) from `service/expense-categories.transport.ts`. A payload carries the id and the server time, never the row's text. After each publish the service writes one `LoggerService.log` line, `expense category created|updated|deleted` with `{ id }`, which carries `requestId` and `staffId` from the request context (D-08, BE-10): until `@Audited()` exists, the event and that line are Node's record of the change.

## Events subscribed

None. Listed in `events/subscribed.ts` (`EXPENSE_CATEGORIES_SUBSCRIBED_EVENTS`).

## Jobs

None.

## Resilience

- **Breaker:** none: no outbound HTTP, no vendor call.
- **Retry policy:** none on writes: an unkeyed `POST` retried could create two rows, and the events are in-process.
- **Pool budget:** shares `POOL.db.api` (`connection_limit` in `DATABASE_URL`, asserted by `check:db`); a list page costs at most seven queries (the page, two counts, two grouped usage counts, the petty-cash probe and, when the table exists, its grouped count); no extra DB or Redis client.

## Legacy parity

Perfex's `admin/expenses/categories` screen, rebuilt from its view:

| Perfex                      | Node                                              | Notes                                                                                                                 |
| --------------------------- | ------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `Expenses::categories`      | `GET /api/v1/expense-categories`                  | the list, with the three usage counts per row                                                                         |
| `Expenses::category`        | `POST` and `PATCH /api/v1/expense-categories/:id` | create and edit; the description stored in the same `nl2br` form                                                      |
| `Expenses::delete_category` | `DELETE /api/v1/expense-categories/:id`           | refused while in use, widened from Perfex's `tblexpenses` check to the accounting mapping and petty cash (D-07, D-15) |

Kept on Perfex as recorded co-writers until their modules migrate (D-14): `POST /admin/expenses/category` (the expense form's inline add, open to non-administrators when Perfex's inline option is on) and `/admin/timesheets/add_expense_category`. A category added there reaches the Node list on its next read but publishes no Node event (accepted, D-14).

Perfex writes an activity-log entry on each change; Node writes no `tblactivity_log` row (D-18): the domain event and the service `log` line are Node's record until Node's own activity log and audit trail exist.

## How to run its tests

```bash
corepack yarn test src/v1/expense-categories          # unit, the repository over a stub client, the gates and the in-process controller e2e spec (no network, no database)
corepack yarn test:int src/v1/expense-categories      # the repository against the local stack (node ../erp-infra/scripts/local-up.mjs first)
```

The int spec writes only rows whose name starts with `int-spec-04.1-04-category` and deletes them before and after the run; it never writes a Perfex-owned table and never reads a local value into an assertion.
